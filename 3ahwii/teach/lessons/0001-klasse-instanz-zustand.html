Klasse, Instanz, Zustand — formalisiert

Du kannst schon Klassen schreiben — der Bruch aus der 2. Klasse hat es bewiesen. Diese Lesson schärft die Begriffe hinter dem Können. Und: Ab heute ist Konto unser Unterrichts-Maßstab — der Bruch war Aufwärmen.

Warum der Bruch nicht mehr reicht

class Bruch hat zwei Felder und eine Rechenart. Das genügt, um Syntax zu lernen — aber nicht, um über Design zu sprechen. Ein Konto hat Identität (die IBAN macht das Konto einzigartig), Zustand, der sich ständig ändert (der Kontostand), und Regeln, die niemals verletzt werden dürfen. Genau diese drei Dinge machen OO-Denken aus.

Die drei Begriffe, sauber getrennt

Begriff Antwortet auf die Frage Am Konto
Klasse Wie bauen wir? class Konto — der Bauplan, existiert einmal
Instanz / Objekt Was existiert jetzt? new Konto("AT12…", 500) — jedes new erzeugt ein neues Ding
Zustand Welche Werte hält dieses Ding gerade? kontostand = 750 — der Feldwert dieser Instanz
Identität ist der vierte Begriff: Ein Konto ist einzigartig, auch wenn zwei Kontos denselben Kontostand haben. === vergleicht Identität (gleicher Speicherplatz), selbst geschriebenes equals() vergleicht Zustand.

Zwei Kontos: a = new Konto("AT1", 500), b = new Konto("AT1", 500). Was gilt?

Zwei new = zwei Instanzen. Der Zustand (Feldwerte) ist gleich, a === b ist false — deshalb schreiben wir equals() für Zustandsvergleich.

Zustand live: Feldwerte sind pro Instanz

export class Konto {
  private kontostand: number;   // Zustand — gehört nur dieser Instanz
  readonly iban: string;        // Identität — nach dem Konstruktor unveränderlich

  constructor(iban: string, startBetrag: number) {
    this.iban = iban;
    this.kontostand = startBetrag;
  }

  einzahlen(betrag: number): void {
    this.kontostand += betrag;   // ändert den Zustand DIESER Instanz
  }

  equals(other: Konto): boolean {
    return this.iban === other.iban;
  }
}

Ändert k1.einzahlen(100), bleibt k2 unberührt. Das ist der ganze Punkt: Zustand lebt pro Instanz, Verhalten teilt sich über die Klasse.

Was verändert einzahlen()?

this.kontostand += … ändert das Feld der Instanz, über die die Methode aufgerufen wurde. Klasse und andere Instanzen bleiben unberührt.

Dein Win heute

Du kannst zu jedem Code sagen: Das ist Bauplan, das ist eine Instanz, das ist Zustand, das ist Identität — und begründen, warum equals() etwas anderes tut als ===. Diese Unterscheidung trägt das gesamte Semester.
