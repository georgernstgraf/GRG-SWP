TS-OOP-Syntax-Cheatsheet

Alles, was UE 1–3 an neuer Syntax brauchen — auf einen Blick, mit Konto-Beispielen.

Klasse mit Zustand und Verhalten (UE 1)

export class Konto {
  private kontostand: number;   // Zustand: Feldwerte dieser Instanz
  readonly iban: string;        // Identität: nach Konstruktor unveränderlich

  constructor(iban: string, startBetrag: number) {
    this.iban = iban;
    this.kontostand = startBetrag;
  }

  einzahlen(betrag: number): void {
    this.kontostand += betrag;
  }

  equals(other: Konto): boolean {
    return this.iban === other.iban;   // Zustandsvergleich, nicht ===
  }

  toString(): string {
    return `Konto ${this.iban} (${this.kontostand} €)`;
  }
}

Kapselung: Sichtbarkeit + getter/setter (UE 2)

export class Sparkonto {
  private kontostand: number;   // privat: keine direkten Schreibzugriffe von außen
  private static readonly ZINS = 0.02;

  constructor(kontostand: number) {
    // Fail-Fast: Invariante im Konstruktor sichern
    if (kontostand < 0) throw new Error("Kontostand darf nicht negativ sein");
    this.kontostand = kontostand;
  }

  // getter: lesender Zugriff bleibt erlaubt
  get kontostand(): number {
    return this.kontostand;
  }

  // Setter nur, wenn geprüft — oder gar kein setter (Änderung über Methoden)
  einzahlen(betrag: number): void {
    if (betrag <= 0) throw new Error("Betrag muss positiv sein");
    this.kontostand += betrag;
  }
}
TS vs. JS: TypeScript-private gilt zur Kompilierzeit; echtes JavaScript-Kapseln tut #feld. Im Unterricht nutzen wir private (kürzer, idiomatisch für TS-Klassen) — den Unterschied kennen heißt Bonuspunkte in der PLF.

Interface als Vertrag (UE 3)

// „was, nicht wie": wer vergleichbar ist, verspricht compareTo
export interface Comparable<T> {
  compareTo(other: T): number;   // <0, 0, >0 — wie bei Bruch üblich
}

export interface Verzinsbar {
  jahresZins(): number;
}

// mehrere Interfaces gleichzeitig implementieren
export class Sparkonto implements Comparable<Sparkonto>, Verzinsbar {
  // …Zustand wie oben…
  compareTo(other: Sparkonto): number {
    return this.kontostand - other.kontostand;
  }
  jahresZins(): number {
    return Sparkonto.ZINS;
  }
}

// Interfaces als Parametertypen: Funktionen hängen am Vertrag, nicht an der Klasse
function bestes<T extends Comparable<T>>(liste: T[]): T {
  // …
}

// structural typing: passt zur Form, auch ohne implements-Deklaration
const kontoOhneImplement = { jahresZins: () => 0.01 };
const v: Verzinsbar = kontoOhneImplement;   // ok — Form stimmt
